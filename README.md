# A03 도서 대출·반납 관리 시스템

제출한 `A03_1차기획서원판.pdf`를 기준으로 작성한 Python CLI 구현물입니다.
정규표현식·구현·검사 강의자료를 참고했습니다. 외부 패키지 설치와 네트워크 연결 없이 실행합니다.

## 실행

Python 3.8 이상이 설치되어 있어야 합니다. 압축 파일을 받은 경우 먼저 압축을 풉니다.
운영체제 터미널에서 `main.py`가 있는 폴더로 이동해 실행합니다.

```sh
cd A03_library
python main.py
```

macOS/Linux에서 명령어가 `python3`인 경우 `python3 main.py`로 실행합니다.
다른 작업 폴더에서 `main.py`의 전체 경로로 실행해도 데이터는 항상 **main.py 옆의 data 폴더**에 저장됩니다.
명령행 인자는 받지 않습니다.

1. 프로그램이 네 CSV의 형식·필드·중복 ID·참조 관계를 확인합니다.
2. 가상 현재 날짜를 `YYYY-MM-DD`로 입력합니다.
3. 관리자 계정이 없다면 최초 관리자 ID·이름·비밀번호를 등록합니다.
4. 방문자 메뉴가 표시됩니다. 관리자는 방금 등록한 계정으로 로그인합니다.

배포 데이터는 헤더만 있는 빈 CSV입니다. 기본 비밀번호나 미리 등록된 계정은 없습니다.
관리자가 도서정보와 권본을 각각 등록한 뒤, 방문자 메뉴에서 일반 회원을 가입시키면 대출을 이용할 수 있습니다.
한 프로그램 인스턴스에서만 사용합니다. 실행 중 CSV를 다른 프로그램으로 편집하지 않습니다.

## 메뉴

| 사용자 | 메뉴 |
|---|---|
| 방문자 | 1 도서 검색 · 2 회원 가입 · 3 로그인 · 0 종료 |
| 회원 | 1 도서 검색·대출 · 2 내 대출 목록 · 3 반납 · 0 로그아웃 |
| 관리자 | 1 도서정보 · 2 권본 · 3 회원 · 4 대출 현황 · 5 반납 · 0 로그아웃 |

관리자의 도서정보·권본·회원·대출 현황 메뉴에는 기획서의 하위 메뉴가 포함되어 있습니다.
회원 가입은 일반 회원 계정만 만들며, 관리자는 최초 등록 절차에서만 생성됩니다.

## 사용 규칙

- 가상 날짜는 실행 시작 때 한 번 입력합니다. 실행 중 자동으로 바뀌지 않습니다. 날짜를 바꾸려면 종료 후 다시 실행합니다.
- 실제 시스템 날짜를 대출·반납·연체 판정에 사용하지 않습니다.
- 최대 5권까지 대출할 수 있습니다. 미반납 연체가 있으면 추가 대출할 수 없습니다.
- 반납기한은 대출일의 14일 뒤이며, 기한 당일은 연체가 아닙니다.
- 같은 도서정보의 이용 가능한 권본 중 가장 작은 권본 ID를 자동 배정합니다.
- ISBN은 선택 입력이며, 하이픈 없는 ASCII 숫자 13자리만 검사합니다. 체크 디지트나 중복 ISBN 검사는 하지 않습니다.
- 도서정보 등록과 권본 등록은 별개입니다. 도서정보만 등록하면 소장 권수는 0권입니다.
- 대출 중인 도서정보의 비활성화 및 권본의 제적은 거부합니다. 과거 대출 기록은 보존합니다.
- 회원은 본인 미반납 기록만, 관리자는 모든 회원의 미반납 기록을 반납할 수 있습니다.

## 입력과 취소

- 메뉴: 앞뒤 공백을 제거한 뒤 화면에 표시된 ASCII 숫자 한 글자를 입력합니다.
- 검색: Enter만 입력하면 취소합니다. 공백만 입력하면 오류를 표시하고 다시 입력받습니다.
- 대출 선택: `0` 또는 Enter만 입력하면 취소합니다. 선행 0이 붙은 숫자도 숫자로 해석합니다.
- 저장 확인: `Y`, `y`, `N`, `n`만 허용합니다. 확인 입력의 앞뒤 공백은 허용하지 않습니다.
- 그 외 입력 단계에서 Ctrl+C를 누르면 현재 작업을 취소하고 직전 메뉴로 돌아갑니다.
- 비밀번호는 `getpass`로 숨겨 입력합니다. 공백도 비밀번호의 일부이며, 공백만으로 된 비밀번호는 사용할 수 없습니다.

비밀번호를 숨길 수 없는 IDE 출력 창·비대화형 환경에서는 일반 터미널을 사용하라는 안내 후 종료합니다.
관리자 조회 표는 열이 많으므로 터미널 창을 넓게 사용하는 편이 좋습니다. 긴 필드도 생략하지 않고 여러 줄로 표시합니다.

## 파일 구성과 담당 코드

```text
A03_library/
  main.py                    시작·가상 날짜·최초 관리자·오류 시 종료
  library/
    auth.py                  회원 ID 중복, 비밀번호 해시, 계정 생성·인증
    validation.py            ID·날짜·검색·도서 필드의 입력 검사
    emoji_ranges.py          검색에서 사용할 고정된 이모지 문자 범위
    service.py               대출·반납·관리 규칙 및 저장 요청
    storage.py               CSV 읽기·쓰기·무결성 검사·저장 복구
    cli.py                   모든 메뉴, 입력 프롬프트, 결과 표
    errors.py                오류 종류
  data/
    users.csv
    books.csv
    copies.csv
    loans.csv
  docs/
    구현기준과_기획서_확인사항.md
    회원가입_로그인_담당안내.md
    UNICODE_LICENSE.txt      포함된 Unicode 문자 데이터의 이용 조건
```

CSV의 열 순서와 형식은 기획서의 데이터 항목을 따릅니다.
정규식의 전체 일치 검사에는 `re.fullmatch`와 명시적인 `[0-9]`, `[A-Za-z]` 범위를 사용합니다.
날짜의 실제 존재 여부, ID 중복, 참조 관계 등은 정규식과 별도로 검사합니다.
검색어는 정규식으로 실행하지 않고 일반 부분 문자열로 비교합니다.

## 데이터 저장과 오류

잘못된 CSV를 발견하면 파일명·행 번호·문제 필드를 표시하고 메뉴를 열지 않습니다.
오류 파일을 임의로 수정하거나 행을 삭제하지 않습니다. 헤더가 없는 빈 파일도 정상 CSV로 간주하지 않습니다.
파일 자체가 없을 때만 헤더를 생성합니다. UTF-8 BOM이 있는 파일도 읽을 수 있습니다.

변경은 매 작업마다 즉시 저장됩니다. 저장이 성공한 뒤에만 완료 메시지를 출력합니다.
도서정보 비활성화처럼 두 CSV를 변경하는 작업은 복구 기록을 이용해 함께 처리합니다.
저장 중 오류가 발생하면 이전 파일들로 되돌리고 종료합니다. 복구에도 실패하면 다음 실행에서 재시도합니다.

저장 도중 생성되는 `data/.transaction.json`과 `.a03-*` 파일은 업무 데이터 파일이 아닌 내부 임시 파일입니다.
특히 `.transaction.json`이 남아 있으면 삭제하지 마세요. 정상 실행의 마지막 저장 상태로 복구하는 데 필요합니다.
복구 기록이 잘못되었으면 덮어쓰지 않고 오류를 안내합니다.

## 확인 상태와 제출 전 사항

- Python 소스 전체에 대해 AST 구문 분석을 수행했습니다.
- **프로그램 실행을 통한 기능 검사와 통합 검사는 아직 수행하지 않았습니다.** 검사 통과나 과제 제출 적합성을 확정하는 자료가 아닙니다.
- 기획서의 본문·그림·예시가 서로 다른 부분과 정의가 빠진 부분은 [구현 기준 문서](docs/구현기준과_기획서_확인사항.md)에 기록했습니다. 구현에서 선택한 해석을 팀에서 확인해야 합니다.
- 원래 기획서 PDF는 수정하지 않았습니다. 위 확인사항을 확정하면 강의자료 #5의 방식에 따라 변경 전후가 드러나는 기획서 수정판에 반영해야 합니다.
- 강의자료 #6의 검사 보고서는 전체 프로그램의 외부 입력과 출력을 기준으로 작성하고, 각 결과를 실제로 관찰한 뒤 기록해야 합니다. 현재 폴더에는 수행하지 않은 검사 결과나 검사 보고서를 넣지 않았습니다.

팀원이 나눠 수정할 때에는 CSV 저장을 `Store`로 일원화하고, 메뉴는 `Console`, 업무 처리는 `Library`의 메서드로 연결해 파일 형식과 동작이 어긋나지 않게 유지하세요.
