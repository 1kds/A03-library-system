# 구현 기준과 기획서 확인사항

기준은 사용자가 제공한 **A03_1차기획서원판.pdf (35쪽)**입니다. 예전 DOCX나 강의의 예시 프로그램 기능을 가져오지 않았습니다.
아래의 쪽 번호는 해당 PDF 본문에 인쇄된 실제 쪽 번호입니다. 원판 목차에 적힌 쪽 번호와 다를 수 있습니다.

이 문서는 구현에서 채택한 해석과 보완 내용을 공개하기 위한 개발 문서이며, 정식 기획서 수정판은 아닙니다.
원판 PDF는 변경하지 않았습니다. 강의자료 #5에서는 기획 자체의 모순·필수 내용 누락을 수정판에 기록하도록 안내합니다.

## 1. 본문과 그림·예시가 충돌하는 부분

| 원판 위치 | 충돌 또는 차이 | 현재 구현에서 채택한 기준 |
|---|---|---|
| 5.2절, 13~16쪽 / 8.2절, 30쪽 | 앞부분·오류 표는 빈 검색어 재입력, 상세 의미 규칙은 Enter만 입력하면 취소 | 5.2절 상세 규칙을 적용. 빈 문자열은 취소, 공백만 있는 문자열은 오류 후 재입력 |
| 5.2절, 14쪽 및 15~16쪽 | 공백만 있는 검색어는 오류라고 정의했지만 예시는 ‘검색된 결과가 없습니다’ 출력 | 의미 규칙을 적용. ‘검색어를 입력해 주세요’ 표시 후 재입력 |
| 3.3절 그림, 8쪽 / 6.1절, 18쪽 | 그림은 재고 없으면 검색 결과로 복귀, 상세 규칙은 회원 메뉴 복귀 | 6.1절과 8.2절을 적용. 안내 후 회원 메뉴로 복귀 |
| 3.3절 그림, 8쪽 / 6.1·6.3절 | 그림에 연체 차단과 반납 Y/N 확인이 생략됨 | 본문의 상세 규칙 적용. 연체 차단·확인 입력 구현 |
| 5.2·7.1.2·7.4절 / 9절 mockup | mockup 일부에는 출판사·분류·상태 등 본문이 요구한 열이 생략됨 | 본문의 필수 열을 모두 표시. 긴 값은 생략 없이 여러 줄 출력 |
| 4.1절, 10쪽 / 5.3절, 16쪽 | 회원 ID의 첫 글자 제한은 5.3절에만 있음 | 더 구체적인 5.3절을 적용. 영문자로 시작하는 ASCII ID만 허용 |

팀에서 위 해석을 확정하면 원판의 일반 규칙·오류 표·그림·mockup을 일치시키는 수정이 필요합니다.

## 2. 원판에 정의가 부족하여 구체화한 동작

| 항목 | 현재 구현 |
|---|---|
| 메뉴 공백 | 5.1절의 앞뒤 공백 제거 규칙을 모든 메뉴에 공통 적용. 공백 제거 후 한 자리 ASCII 숫자만 허용 |
| ID 입력 공백 | 회원가입·로그인·도서정보/권본/대출 ID 입력은 공백을 자동 제거하지 않음. 규정된 ID 문자열을 그대로 사용 |
| ID 대소문자 | 가입 중복·로그인·관리자 회원 ID 검색은 대소문자 무시. 도서정보/권본/대출 ID 접두어는 규정대로 대문자만 허용 |
| 이름 검색 | 앞뒤 공백을 제거한 비어 있지 않은 검색 문자열을 표시 이름에 그대로 포함하는지 비교. 이름의 대소문자는 구별 |
| 대출 번호 | 6.1절에 따라 앞뒤 공백 제거 후 ASCII 숫자로 비교. `0001`은 1, `00`은 0으로 해석. Enter만 입력하면 취소지만 공백만 입력하면 문법 오류 |
| Y/N 공백 | 7.6절의 ‘Y, y, N, n만 허용’을 그대로 적용. ` Y `는 오류 |
| 검색 금지 문자 | 역슬래시·세로줄과 Unicode Emoji 16.0의 Emoji 속성 문자를 금지. 숫자·#·* 단독은 허용하고 키캡 결합·변형 선택자·ZWJ는 금지. 그 외 허용 문자 종류는 공백류·ASCII 영문/숫자·한글·허용 기호/문장부호. 이모지의 기준 버전은 원판에 없으므로 팀 확인 필요 |
| 신규 도서정보/권본 ID | 기존 ID 숫자 부분의 최댓값+1, 네 자리 0 채움. 9999를 넘으면 변경 없이 안내 후 해당 메뉴 복귀. 대출 ID는 원판의 999999 제한 적용 |
| 가상 날짜 범위 | 네 자리 연도와 Python 표준 date가 지원하는 소급 그레고리력 0001-01-01~9999-12-31. 앞뒤 공백은 허용하지 않음 |
| 날짜 상한에서 대출 | 현재 날짜는 입력 가능하더라도 14일 뒤가 9999-12-31을 넘으면 신규 대출만 거부. 기존 날짜를 임의로 바꾸지 않음 |
| 가상 날짜를 과거로 입력 | 원판에 제한이 없어 허용. 반납일도 입력된 가상 날짜를 기록하며 대출일보다 과거라는 이유로 별도 차단하지 않음 |
| Ctrl+C, 직전 메뉴가 없는 경우 | 시작 날짜 입력·최초 관리자 등록 중에는 실행 종료. 일반 기능 입력 중에는 직전 메뉴. 하위 메뉴 자체에서 누르면 상위 메뉴. 최상위 방문자 메뉴에서는 종료 |
| 지속되는 EOF | 기능 입력의 취소 후 메뉴를 표시하고 종료. 입력 스트림이 계속 닫혀 있으면 재입력할 수 없으므로 무한 반복하지 않음 |
| 저장 중 Ctrl+C | 파일 교체와 메모리 갱신을 마친 뒤 인터럽트를 전달. 저장이 끝난 데이터는 유지 |
| 관리자 반납에서 이미 반납된 ID | 사유를 안내하고 대출 ID 재입력. 없는 ID·형식 오류도 각 사유를 표시하고 재입력 |
| 회원 반납 목록이 비었을 때 | 대출 중인 도서가 없음을 안내하고 Enter 대기 후 회원 메뉴 복귀 |
| 잘못된 관리 대상 ID | 형식/존재 오류는 같은 ID 입력에서 재입력. 이미 비활성·이미 제적·대출 중 등 작업 불가 상태는 안내 후 해당 하위 메뉴 복귀 |
| 조회 뒤 복귀 | 결과를 출력한 일반 조회는 Enter 대기 후 해당 메뉴 복귀. 기록 없는 대출 현황 필터는 7.4절대로 즉시 메뉴 복귀 |

이모지 분류표는 [Unicode Emoji 16.0 공식 데이터](https://www.unicode.org/Public/16.0.0/ucd/emoji/emoji-data.txt)의 범위를 코드에 포함한 것입니다. 실행 중 인터넷 접속이나 외부 패키지가 필요하지 않습니다. 해당 데이터의 이용 조건은 `UNICODE_LICENSE.txt`에 포함했습니다.

## 3. 저장 형식과 무결성 검사

네 CSV의 필드 순서, 빈 선택 값, true/false 표기, 식별자 형식은 4절과 9.6절을 따릅니다.
도서정보·권본·대출의 자동 ID는 사용 이력이 사라지지 않도록 기록을 삭제하지 않으며 최댓값 다음 번호를 부여합니다.

검사하는 내용은 다음과 같습니다.

- UTF-8 인코딩, 헤더 열 이름/순서, CSV 인용 문법, 열 개수.
- 회원 ID/표시 이름/해시/권한/활성 값, 도서정보 필수값과 길이·ISBN·KDC, 권본 ID/활성 값, 대출 날짜 형식.
- 각 기본 ID의 중복. 회원 ID는 대소문자를 무시하여 중복 검사.
- 권본의 도서정보 참조, 대출의 회원·권본 참조. 참조 필드는 저장된 ID와 정확히 일치해야 함.
- 관리자 계정이 대출자가 되는 기록, 같은 권본을 가리키는 복수 활성 대출.
- 반납기한이 대출일의 14일 뒤인지, 제적 권본에 활성 대출이 있는지, 비활성 도서정보에 활성 권본이 있는지.

마지막 항목은 6.1·7.1.5·7.2.4절의 정상 처리 결과가 데이터에도 유지되도록 구체화한 검사입니다.
모든 파일의 읽기·검사가 끝나기 전에 누락 파일의 헤더를 생성하지 않습니다. 따라서 오류 실행에서 기존 데이터는 바뀌지 않습니다.
CSV 오류에는 물리적인 파일 행 번호를 표시합니다. 표준 CSV 인용 규칙으로 여러 줄 필드도 읽을 수 있습니다.

원판에는 비밀번호 해시의 구체적인 포맷이 없어 `pbkdf2_sha256$600000$salt_hex$digest_hex`로 정했습니다.
salt는 계정마다 생성한 16바이트 난수입니다. 다른 해시 형식으로 만든 기존 데이터는 자동 변환하지 않습니다.

파일은 UTF-8 CSV로 직접 읽고 씁니다. 데이터베이스나 외부 저장 서비스를 사용하지 않습니다.
한 작업에서 두 파일을 바꿀 때에는 내부 복구 기록과 같은 폴더의 임시 파일을 이용합니다. 업무 데이터는 계속 네 CSV에 저장됩니다.
이전 실행에서 중단된 **자체 저장 작업의 복구**와 **손상된 CSV를 자동 수정하는 것**은 구분합니다. 후자는 수행하지 않습니다.

## 4. 강의자료 적용 범위와 확인 상태

- #4: ID·ASCII 숫자·날짜 문법은 정규식으로 전체 일치 검사. 날짜 존재 여부·중복·참조·대출 조건은 별도의 의미 검사.
- #5: 기획서의 메뉴·권한·입출력·예외 이동을 구현하고, 웹/예약/연장/계정 삭제 등 범위 밖 기능은 구현하지 않음. 서로 다른 해석이 가능한 부분은 위에 공개.
- #6: 검사 보고서는 기획서의 각 분기와 입력 경계값을 기준으로 실제 전체 프로그램을 검사한 결과로 작성해야 함을 확인.

현재 소스의 문법 분석은 완료했으나 **실행을 통한 기능 검사·통합 검사는 아직 수행하지 않았습니다**.
이 문서는 테스트 통과 기록이나 검사 보고서를 대신하지 않습니다.
