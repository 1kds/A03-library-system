# 회원가입·로그인 담당 안내

## 전체 흐름

회원 가입은 `Console.signup` → 입력 검사 → `Library.signup` → `auth.make_account` → `Store.commit` 순서입니다.
로그인은 `Console.login` → `Library.login` → `auth.authenticate` → 권한별 메뉴 순서입니다.

입력은 CLI, 계정 규칙은 auth, CSV 저장은 storage가 맡습니다.
회원가입 코드에서 CSV를 따로 열어 저장하면 다른 기능의 메모리 상태와 파일 상태가 달라질 수 있으므로 `Library.signup`을 통해 저장합니다.

## 담당 파일에서 볼 함수

| 위치 | 함수 | 역할 |
|---|---|---|
| `validation.py` | `user_id` | 영문자로 시작, ASCII 영문·숫자·밑줄 4~20자 검사 |
| `validation.py` | `display_name` | 앞뒤 공백 제거, 1~40자 검사 |
| `validation.py` | `password` | 8~64자, 공백만으로 구성되지 않았는지 검사 |
| `auth.py` | `check_new_id` | 비활성 계정까지 포함해 대소문자 무시 중복 검사 |
| `auth.py` | `hash_password` | 임의 salt와 PBKDF2-HMAC-SHA256으로 저장할 해시 생성 |
| `auth.py` | `verify_password` | 입력한 비밀번호를 저장 해시와 비교 |
| `auth.py` | `make_account` | users.csv에 저장할 계정 딕셔너리 생성 |
| `auth.py` | `authenticate` | 활성 계정 인증 성공 시 계정 복사본, 실패 시 None 반환 |
| `cli.py` | `Console.signup` | 각 항목 입력, 오류 항목 재입력, 비밀번호 확인 |
| `cli.py` | `Console.login` | 인증 실패 안내 또는 회원/관리자 메뉴 연결 |

## 저장하는 정보

users.csv의 열은 `user_id,display_name,password_hash,role,active`입니다.

- ID는 가입자가 입력한 대소문자를 보존합니다. 중복 검사와 로그인 비교에서는 대소문자를 무시합니다.
- 신규 일반 회원은 `role=member`, 최초 관리자는 `role=admin`입니다.
- 신규 계정의 `active`는 `true`입니다.
- 비밀번호 확인 값은 일치 여부만 검사하고 저장하지 않습니다.
- 원문 비밀번호는 CSV와 로그에 남기지 않습니다.
- 동일한 비밀번호라도 계정별 임의 salt가 달라 해시 문자열이 다릅니다.

해시 문자열은 `pbkdf2_sha256$600000$32자리_salt_hex$64자리_digest_hex` 형식입니다.
기획서의 `<검증용 해시 값>`은 설명용 자리표시자이므로 실제 users.csv에 그대로 넣을 수 없습니다.

## 연결할 때 지킬 동작

1. ID 형식 오류와 중복 오류는 ID만 다시 입력받습니다.
2. 이름 오류는 이름만 다시 입력받습니다.
3. 비밀번호 오류는 비밀번호만 다시 입력받습니다. 영문/숫자 조합 같은 추가 조건을 붙이지 않습니다.
4. 확인 비밀번호가 다르면 확인 값만 다시 입력받습니다.
5. 회원 가입이 끝나도 자동 로그인하지 않고 방문자 메뉴로 돌아갑니다.
6. 로그인 실패는 ID 미존재·비밀번호 불일치·비활성을 구분하지 않고 같은 문구로 안내한 뒤 방문자 메뉴로 돌아갑니다.
7. 로그아웃하면 `Library.user`를 `None`으로 초기화합니다.
8. `Library.require`가 업무 처리 직전에도 권한을 검사하므로 메뉴 숨김과 업무 권한 검사가 함께 적용됩니다.

로그인 ID의 공백 처리와 관리자 회원 검색의 대소문자 처리 등 기획서에 정의가 부족한 부분은 별도 구현 기준 문서에 기록했습니다.
